# 质量报告：只判内容，不判格式

```bash
fg quality          # 完整
fg quality --brief  # 去掉冲突明细
fg validate         # 只看事实与实体层面的问题
```

## 它判什么、不判什么

**判的是「这张图能不能被人用来做判断」：**

- 这个数字有没有单位、币种、期间、合并口径 —— 没有就是不可用的数。
- 这条 `quote` 能不能在落盘原文里找到 —— 找不到就说明是凭记忆写的。
- 这个公司节点的属性够不够支撑判断，覆盖了几个维度组。
- 这条边除了「有关系」之外，说不说得清机制、带不带得起分析。
- 这条 10 跳路径是真的跨了机制层，还是同一种关系接龙。
- 检索回来的数据有多少真的进了图。

**不判的：**

- 不检查 JSON 有没有某个 key、字段顺序、文件命名。
- 不算工件哈希、不比对快照摘要、不做任何签名校验。
- 不因为「模板里有 40 个字段而你只填了 12 个」就判失败——判的是**已知且有证据的**属性数，空字段填满了只会更糟。
- 不把节点数量本身当成目标：`business_node_count` 统计的是有证据的业务节点，拆分同一实体、批量导入空壳都不会让这个数变好看。

格式对了但内容空的图，这份报告一定判 `ok=false`；格式随意但内容扎实的图，它会通过。

## 三个质量档

`fg session new --profile` 或 `fg session set --profile` 设定。档位是**目标**，不是准入条件。

| 指标 | `probe` 探路 | `standard` 标准 | `deep` 纵深 |
| --- | --- | --- | --- |
| 锚点已知属性数 | ≥12 | ≥24 | ≥40 |
| 有证据业务节点 | ≥30 | ≥120 | ≥300 |
| 可分析边占比 | ≥60% | ≥80% | ≥90% |
| 用到的语义层 | ≥3 | ≥6 | 8 |
| 信息交代率 | ≥50% | ≥75% | ≥85% |
| 独立实质路径 | 6跳×1 | 6跳×8 + 8跳×3 | 6跳×20 + 10跳×8 |

另外三项与档位无关，始终按同一标准判：数值可用率（有单位/币种 + 有期间）≥95%、锚点属性覆盖 ≥5 个维度组、空泛关系为 0。

`probe` 适合先摸清一个主题值不值得做；`deep` 是机构级交付。**不确定就用 `standard`**，做到一半发现要更深再往上调。

## 逐项含义与修法

### 证据

| finding | 说明 | 修法 |
| --- | --- | --- |
| `quote 在 h-xxxx 的返回里找不到` | 引文是改写的或来自别处 | 回到 `fg harvest show <id> --part data --grep …` 摘原文，不要凭记忆 |
| `缺 harvest_id` | 这条事实来源不明 | 补上，或者先去检索 |
| `数值缺单位/币种/百分比标记` | 读到的人无法判断量级 | 补 `unit` / `currency`；万元和元差一万倍 |
| `数值缺 period` | 不知道是哪一期 | 补 `period`，区分时点（instant）与区间（duration） |
| `inference 类事实必须写 basis_fact_ids` | 推断没说依据 | 写依据事实 ID 与 `rule`；没有依据就不该断言 |
| `推断依赖成环` | A 依据 B、B 依据 A | 打断环，找到真正的地基事实 |

### 节点深度

| finding | 说明 | 修法 |
| --- | --- | --- |
| `锚点只有 N 个有证据的属性` | 收割没挖尽 | `fg harvest show <id> --part cells --unused-only`。一次利润表检索应产出几十条属性事实 |
| `锚点属性只覆盖 N 个维度组` | 只查了一个方向 | 按 `NODE_PROFILE.md` 的八组补检索，通常缺所有权、治理、风险 |
| `N 个业务节点只有名字没有任何属性` | 为了连边随手造的节点 | 补属性，或者删掉。空壳节点让图看起来大而实际空 |
| `有证据的业务节点 N 个，目标 ≥M` | 扇区没铺开 | 按 `LAZYSEARCH.md` 的十扇区扩，别拆分同一实体凑数 |

### 边可分析性

| finding | 说明 | 修法 |
| --- | --- | --- |
| `关系名空泛` | 写了「相关/影响/关联」 | 换成具体金融动作，见 `EDGE_SEMANTICS.md` |
| `可分析边占比不足` | 缺机制或缺属性 | 看 `missing_mechanism` / `missing_attrs` 两个清单逐条补 |
| `只用到 N 个语义层` | 机制层次不全 | 缺的通常是政策、预期、二阶反馈 |

### 数值与冲突

| finding | 说明 | 修法 |
| --- | --- | --- |
| `numeric_usable_ratio` 低 | 大量数值缺口径 | 见上 |
| `conflicts` | 同主体同指标同期间不同值 | **不要静默取一个。** 常见原因是报告期 vs 时点、合并 vs 母公司、原始 vs 重述、复权口径不同。分清了就分成两条不同期间/口径的事实；分不清就 `fg align` 交给用户 |

### 结构与纵深

| finding | 说明 | 修法 |
| --- | --- | --- |
| `N 个业务节点没有任何边` | 游离资料 | 接上关系或删除 |
| `叶节点占比高` | 一根主干挂一圈卫星 | 补交叉边 |
| `2-core 只占 N%、桥边率 M%` | 图是树/链，零交叉验证 | 给同一结论找第二条边不重叠的通路 |
| `从锚点只能走到 N% 的业务节点` | 有一片与主题不通 | 那片要么接上，要么它本来就不属于这张图 |
| `独立 N+ 跳路径只有 M 条` | 纵深不足 | **先看 `fg depth` 的 `weak_because`**，跨层不够/关系重复/某跳无证据各有各的补法，都不是再接一跳能解决的 |
| `机制问题未被回答` | 用户点名的链路走不通 | 优先级最高，见 `DEPTH.md` |

### 信息利用

| finding | 说明 | 修法 |
| --- | --- | --- |
| `N 次收割整个还没挖过` | 检索了但没用 | `fg harvest list --state unmined` 逐个挖 |
| `只有 N% 进了图、M% 被交代过` | 挖掘停在「看过就算」 | `fg usage` 找最差的几次，`--part cells --unused-only` 逐格处理；确实不用的 `fg harvest dispose` 写理由 |

## 修复顺序

从上往下修，前面的会连带解决后面的：

1. **证据类 error**（quote 找不到、缺口径、推断无依据）—— 这些是数据本身不可靠，先修。
2. **未回答的机制问题** —— 用户点名要能走通的链路。
3. **未挖的收割 + 信息利用率** —— 挖掘会同时长出节点属性和边，一次解决好几项。
4. **锚点属性与维度覆盖** —— 靠补检索，不靠填空。
5. **边的机制与属性** —— 写不出机制的边说明那一跳还没研究透。
6. **纵深与结构** —— 前五项做好之后，纵深通常自然到位；仍不到位再针对性补层。
7. **覆盖广度** —— 最后再考虑扩大规模。规模是结果，不是手段。

**不要倒着做。** 先冲节点数量、后补属性和机制，会得到一张大而空的图，而且返工量最大。

## `ok=false` 意味着什么

只意味着两件事：

1. 现在不该对外声称这张图达标了，也不该把它的结论当成可用结论。
2. `fg neo4j load` 会拒绝装生产库，除非你明确加 `--force`。

它**不**意味着流程被锁住。你可以继续检索、继续挖掘、继续对齐、继续 `--dry-run` 看形状、继续 `--force` 装个中间快照看图。质量报告是尺子，不是闸门。
