# 质量报告：只判内容，不判规模

```bash
fg quality          # 完整
fg quality --brief  # 去掉冲突明细
fg validate         # 只看事实与实体层面的问题
fg brief            # 下一步该检索什么（扇区缺口、未用单元格、根目录 stray 文件）
```

## 它判什么、不判什么

**判的是「这张图能不能被人用来做判断」：**

- 这个数字有没有单位、币种、期间、合并口径 —— 没有就是不可用的数。
- 这条 `quote` 能不能在落盘原文里找到 —— 找不到就说明是凭记忆写的。
- 这条边的关系名是不是 2–8 字短语 —— 写成句子，Browser 图例读不动。
- 这条边除了「有关系」之外，说不说得清机制、带不带得起分析。
- 这条路径是真的跨了机制层，还是同一种关系接龙。
- 检索回来的数据有多少真的进了图。

**不判的：**

- 不检查 JSON 有没有某个 key、字段顺序、文件命名。
- 不算工件哈希、不比对快照摘要、不做任何签名校验。
- **不设「必须有 XXX 个节点 / XXX 条边 / XXX 跳」的门槛。** 规模是发掘的结果，不是准入条件。
- 不因为「模板里有 40 个字段而你只填了 12 个」就判失败——判的是**已知且有证据的**属性数。

`ok=false` 只在还有**证据缺陷**（引文找不到、端点悬空、数值缺口径）或**边名写成句子/空泛词**时出现。节点少、跳数浅、扇区没铺开，会以 `level: guide` 告诉你下一步去问什么，不会把 `ok` 打成 false，也**不会拦住 `fg neo4j load`**。

## 质量档是方向感，不是门禁

`fg session new --profile` 只影响 `fg brief` / `fg quality` 说话的语气，用来提醒「按这个方向还可以再挖」。它**不**产生 error，**不**阻止装库。

不确定就用 `standard`。想先摸清一个主题值不值得做，用 `probe`；要机构级交付再调 `deep`。

真正让图变深、变大的办法：按 `LAZYSEARCH.md` 的十个扇区继续检索，把 `fg usage` 里还悬着的单元格挖尽。`fg brief` 会直接给出下一条该问的问题。

## 逐项含义与修法

### 证据（这些才是 error）

| finding | 说明 | 修法 |
| --- | --- | --- |
| `quote 在 h-xxxx 的返回里找不到` | 引文是改写的或来自别处 | 回到 `fg harvest show <id> --part data --grep …` 摘原文，不要凭记忆 |
| `缺 harvest_id` | 这条事实来源不明 | 补上，或者先去检索 |
| `数值缺单位/币种/百分比标记` | 读到的人无法判断量级 | 补 `unit` / `currency`；万元和元差一万倍 |
| `数值缺 period` | 不知道是哪一期 | 补 `period`，区分时点（instant）与区间（duration） |
| `inference 类事实必须写 basis_fact_ids` | 推断没说依据 | 写依据事实 ID 与 `rule`；没有依据就不该断言 |
| `推断依赖成环` | A 依据 B、B 依据 A | 打断环，找到真正的地基事实 |
| `关系名空泛或写成了句子` | 「相关」或一整句当关系类型 | 改成 2–8 字短语，见 `EDGE_SEMANTICS.md` |

### 下一步发掘（这些是 guide，不是门槛）

| finding | 说明 | 修法 |
| --- | --- | --- |
| `还没覆盖的检索扇区` | 十扇区里有的还没问 | `fg brief` 里的 `sectors.missing` 带下一条查询；每次 `fg search` 加 `--tag` |
| `锚点只有 N 个有证据的属性` | 收割没挖尽 | `fg harvest show <id> --part cells --unused-only`。一次利润表检索应产出几十条属性事实 |
| `锚点属性只覆盖 N 个维度组` | 只查了一个方向 | 按 `NODE_PROFILE.md` 的八组补检索，通常缺所有权、治理、风险 |
| `N 个业务节点只有名字` | 为了连边随手造的节点 | 补属性，或者删掉 |
| `缺机制 / 缺属性` | 边连上了但还不能分析 | 写不出机制说明那一跳还没研究透 |
| `只用到 N 个语义层` | 机制层次不全 | 缺的通常是政策、预期、二阶反馈 → 扇区 9、10 |
| `N 次收割还标着 unmined` | 检索了但没用 | 草稿写进会话 `drafts/`，`fg harvest mine <id> --done` |
| `只有 N% 进了图` | 挖掘停在「看过就算」 | `fg usage` 找最差的几次，逐格处理；确实不用的 `dispose` |
| `机制问题还未走通` | 用户点名的链路不通 | 优先级最高，见 `DEPTH.md`；补缺的那几跳，不要去凑节点数 |

### 结构（warn）

| finding | 说明 | 修法 |
| --- | --- | --- |
| `N 个业务节点没有任何边` | 游离资料 | 接上关系或删除 |
| `叶节点占比高` | 一根主干挂一圈卫星 | 补交叉边 |
| `2-core 只占 N%、桥边率 M%` | 图是树/链，零交叉验证 | 给同一结论找第二条边不重叠的通路 |
| `从锚点只能走到 N% 的业务节点` | 有一片与主题不通 | 那片要么接上，要么它本来就不属于这张图 |
| `conflicts` | 同主体同指标同期间不同值 | **不要静默取一个。** `fg align` 交给用户判 |

## 修复顺序

从上往下修，前面的会连带解决后面的：

1. **证据类 error**（quote 找不到、缺口径、推断无依据、边名是句子）—— 这些是数据本身不可靠，先修。
2. **未走通的机制问题** —— 用户点名要能走通的链路。
3. **未挖的收割 + 未覆盖扇区** —— `fg brief` 会给出下一条查询。挖掘会同时长出节点属性和边。
4. **锚点属性与维度覆盖** —— 靠补检索，不靠填空。
5. **边的机制与属性** —— 写不出机制的边说明那一跳还没研究透。
6. **结构交叉验证** —— 给同一结论找第二条独立通路。

**不要倒着做。** 先冲节点数量、后补属性和机制，会得到一张大而空的图，而且返工量最大。也不要为了让某个数字好看去接龙。

## `ok=false` 意味着什么

只意味着：现在不该把这张图的数字和关系当成可用结论（还有引文对不上，或边名读不懂）。

它**不**意味着流程被锁住，也**不**阻止 `fg neo4j load`。装库只在仍有**证据类**错误时拒绝（引文找不到、端点悬空）；规模、跳数、扇区覆盖从不拦截。确实要把一份已知坏证据的快照装进去看形状，才需要 `--force`。

## 报告落在哪

```
financial-graph-sessions/<会话>/reports/quality.json
financial-graph-sessions/<会话>/reports/depth.json
financial-graph-sessions/<会话>/reports/harvest-usage.json
financial-graph-sessions/<会话>/drafts/          ← 实体/事实草稿，不要写到工作区根目录
```

都是明文 JSON，`fg export` 会一起带走。
