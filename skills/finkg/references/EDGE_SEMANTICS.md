# 边：既要一眼读懂，又要能继续往下分析

## 一条合格的边长什么样

```json
{
  "subject": "E-ganfeng", "predicate": "向客户供应",
  "object": {"kind": "entity", "entity": "E-catl"},
  "epistemic": "reported", "confidence": "high",
  "harvest_id": "h-0007",
  "quote": "赣锋锂业 | 宁德时代 | 长期供货协议 | 2025-2027 | 指数联动定价",
  "target": {
    "kind": "edge", "from": "E-ganfeng", "to": "E-catl",
    "relation": "向客户长协供应电池级碳酸锂",
    "layer": "supply_operation",
    "mechanism": "长协锁量、价格随基准指数联动，锂价波动经采购成本直接进入宁德时代营业成本",
    "attrs": {"合同类型": "长期协议", "有效期间": "2025-2027",
              "计价方式": "指数联动", "锁量": "不低于8万吨/年",
              "占采购比": "约15%", "数据来源": "供货协议公告"}
  }
}
```

三个必备件，缺一个这条边就不完整：

| 必备件 | 作用 | 缺了会怎样 |
| --- | --- | --- |
| `relation` 具体中文动作 | 用户不用点开就知道这两个实体是什么关系 | 「相关」「影响」这类词直接判 error |
| `mechanism` 一句话机制 | 说清这条关系凭什么成立、如何传导 | 纵深分析在这一跳断掉，路径判为非实质 |
| `attrs` 量化/时间属性 | 让这条边本身可以被继续分析和比较 | 只知道「有关系」，无法判断强弱、时点、方向 |

`fg quality` 的 `analyzable_ratio` 就是同时满足这三件 + 有事实支撑的边占比。

## 关系名怎么写

**句式：动作 + 对象/方式 + 限定。** 主语是 `from`，宾语是 `to`，关系名里不要重复端点名称。

| 语义层 | 具体动作示例 |
| --- | --- |
**政策与监管** | 提高动力电池能量密度准入门槛、将某品类纳入出口管制清单、对某公司作出行政处罚、给予增值税即征即退、要求限期整改、暂停某项业务资质
**法律与所有权** | 由最终母公司控制、直接持有股份、通过一致行动协议共同控制、为子公司债务提供连带担保、将股权质押给银行、作为发行人发行普通股、在创业板挂牌交易
**供给与运营** | 向客户长协供应电池级碳酸锂、为某产品提供代工制造、租赁某生产设施、依赖单一供应商采购关键部件、在某基地投产产线、外购某中间品
**需求与终端市场** | 向整车客户供应动力电池系统、拉动某原料需求、与某产品形成替代关系、在某终端市场竞争同一订单、被纳入某集采名录
**公司行为与战略** | 收购某公司控股权、剥离某业务分部、与某方设立合资公司、宣布扩产计划、发起价格调整、启动股份回购
**财务与资本** | 由某分部贡献主营业务收入、以某项目计提资产减值、发行公司债券融资、取得银行授信、向股东分配现金红利、确认对联营企业投资收益
**预期与估值** | 经订单节奏改变市场盈利预期、被分析师上调目标价、纳入某指数带来被动配置、以业绩指引锚定一致预期
**风险与二阶反馈** | 经应收账款形成客户信用敞口、因原料集中度形成断供风险、通过质押率下降触发追加担保、因股价下跌放大商誉减值压力

写不出具体动作，说明这一跳还没研究清楚。这时该回去检索，不是先把边连上再说。

## 明确禁止的关系名

`相关`、`有关`、`关联`、`关系`、`影响`、`联系`、`涉及`、`对应`、`存在关系`、`相互影响`，以及它们的英文（`related`、`affects`、`linked`、`associated`、`connected`）。

「影响」尤其常见。它不是错的方向，而是**信息量为零**——A 影响 B 可以指供货、竞争、持股、政策约束、预期传导中的任何一种。把它换成实际发生的那一种动作。

关系名少于 3 个字符，或者不含汉字，也会被点名。

## 每一族边该带哪些属性

| 关系族 | 至少带 |
| --- | --- |
| 持股 / 控制 | 持股比例、持股数量、股东性质、直接还是间接、报告期、是否一致行动 |
| 供应 / 采购 | 品类、数量或金额、占对方采购/销售比、合同类型、计价方式、有效期间、提前期 |
| 客户 / 销售 | 收入金额、占营收比、期间、是否前五大客户、结算方式 |
| 分部 / 产品 | 收入、成本、毛利率、占比、同比、报告期、口径 |
| 债务 / 担保 | 本金、币种、利率、期限、担保方式、余额时点 |
| 政策 / 监管 | 发布机构、生效时间、适用范围、约束强度、过渡期、罚则 |
| 事件 | 宣布/生效/完成时间、金额、条件、进展状态 |
| 竞争 / 替代 | 重叠市场、份额、替代弹性、价差、期间 |
| 预期 / 估值 | 观察指标、传导时滞、方向、幅度、预测机构、发布时间 |
| 风险传导 | 触发条件、领先指标、传导时滞、影响量级、缓释措施、失效条件 |

属性名同样用中文。数值属性要带单位（写在属性名里，如 `占营收比(%)`、`金额(亿元)`，或值本身带单位后缀）。

## 方向

方向按**动作发出方 → 承受方**：

- 供应：供应商 → 客户
- 持股：股东 → 被持股公司
- 政策约束：政策/监管机构 → 被约束主体
- 预期传导：驱动因素 → 被定价的证券

对称关系（竞争、替代、合资）也要选一个方向写，用关系名表达对称性（「与某产品形成替代关系」）。纵深分析默认按无向遍历，所以方向写错不会让路径消失，但会让 `fg neo4j hop --directed` 和机制方向判断出错。

## 认识状态

边上的 `epistemic` 决定这一跳算不算硬证据：

- `reported` / `observed`：来自披露或市场数据，是纵深的地基。
- `estimate` / `forecast` / `inference` / `scenario`：必须写 `basis_fact_ids`（依据哪些已接受事实）和 `rule`（推断规则）。
- **一条路径上连续超过 2 跳都是推断类，整条路径判为悬空。** 推断边要夹在有据可查的边之间。

推断边还应该在 `mechanism` 里写清替代解释和失效条件。「若客户改用磷酸铁锂路线，此传导减弱」这种一句话，比多连三条边有价值。

## 什么时候合并、什么时候拆分

编译时会自动合并 `(from, to, relation, period)` 完全相同的边，并把事实与属性并到一起。

**该拆成多条边的情况：**

- 不同报告期的同一关系（2024 年持股 12%、2025 年持股 15%）→ 用 `period` 区分。
- 同一对实体之间的不同动作（既供应原料又互为竞争对手）→ 两个 `relation`。
- 同一动作但机制不同（直接持股 vs 通过合伙企业间接持股）→ 关系名里体现。

**该合并的情况：** 同一份公告里拆出来的多条属性，应该并到**一条**边的 `attrs` 上，而不是造出多条只差一个属性的平行边。重复边会在质量报告里体现为关系词表虚高、`mean_attr_count` 偏低。

## 自查

```bash
fg quality        # 看 vague_relations / missing_mechanism / missing_attrs / mean_attr_count
fg node E-catl    # 看这个节点的进出边，读一遍关系名
```

把某个节点的进出边关系名连起来读一遍。如果读出来像一段能讲给人听的业务描述，边就写对了；如果读出来是一串「相关、影响、涉及」，那图还没开始有价值。
