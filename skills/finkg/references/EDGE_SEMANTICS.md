# 边：关系名是短语，细节在属性上

Browser 图例和路径阅读靠的是**关系类型**。写成一整句，图例会挤成墙，多跳路径也没法扫读。

## 一条合格的边长什么样

```json
{
  "subject": "E-ganfeng", "predicate": "供应",
  "object": {"kind": "entity", "entity": "E-catl"},
  "epistemic": "reported", "confidence": "high",
  "harvest_id": "h-0007",
  "quote": "赣锋锂业 | 宁德时代 | 长期供货协议 | 2025-2027 | 指数联动定价",
  "target": {
    "kind": "edge", "from": "E-ganfeng", "to": "E-catl",
    "relation": "长协供应",
    "layer": "supply_operation",
    "mechanism": "长协锁量、价格随基准指数联动，锂价波动经采购成本直接进入宁德时代营业成本",
    "attrs": {"品类": "电池级碳酸锂", "合同类型": "长期协议", "有效期间": "2025-2027",
              "计价方式": "指数联动", "锁量": "不低于8万吨/年", "占采购比": "约15%",
              "数据来源": "供货协议公告"}
  }
}
```

三个必备件，缺一个这条边就不完整：

| 必备件 | 作用 | 缺了会怎样 |
| --- | --- | --- |
| `relation` 2–8 字中文短语 | 图例和路径能一眼扫过 | 空泛词判 error；整句（>8 字）也判 error |
| `mechanism` 一句话机制 | 说清这条关系凭什么成立、如何传导 | 纵深分析在这一跳断掉，路径判为非实质 |
| `attrs` 量化/时间/对象属性 | 品类、比例、期间、对象都放这里 | 只知道「有关系」，无法判断强弱、时点、方向 |

`from` 是主语，`to` 是宾语，**不要把端点名称写进关系名**。

## 关系名怎么写

**词或动宾短语，2–8 个汉字，不要标点、不要空白、不要写成句子。**

| 语义层 | 合格短语 | 不要写成 |
| --- | --- | --- |
| 政策与监管 | 准入约束、出口管制、行政处罚、税收优惠、限期整改、暂停资质 | 提高动力电池能量密度准入门槛 |
| 法律与所有权 | 控制、持股、共同控制、连带担保、股权质押、发行、挂牌 | 作为第一大股东直接持有股份、在创业板挂牌交易 |
| 供给与运营 | 长协供应、代工、租赁、依赖采购、投产、外购 | 向客户长协供应电池级碳酸锂 |
| 需求与终端市场 | 供应、拉动需求、替代、竞争、纳入集采 | 向整车客户供应动力电池系统 |
| 公司行为与战略 | 收购、剥离、合资、扩产、调价、回购 | 收购某公司控股权 |
| 财务与资本 | 贡献收入、计提减值、发债融资、取得授信、现金分红、确认投资收益 | 由动力电池系统分部贡献主营业务收入 |
| 预期与估值 | 预期传导、上调目标价、指数纳入、锚定预期 | 经订单节奏改变市场盈利预期 |
| 风险与二阶反馈 | 信用敞口、断供风险、追加担保、放大减值 | 经应收账款形成客户信用敞口 |

对象、品类、板块、阈值、比例一律进 `attrs`：

- `长协供应` + `attrs.品类 = 电池级碳酸锂`
- `挂牌` + `attrs.板块 = 创业板`
- `准入约束` + `attrs.约束阈值 = 125Wh/kg`
- `持股` + `attrs.持股比例(%) = 24.68`

写不出短语，说明这一跳还没研究清楚。这时该回去检索，不是先把边连上再说。

## 明确禁止的关系名

`相关`、`有关`、`关联`、`关系`、`影响`、`联系`、`涉及`、`对应`、`存在关系`、`相互影响`，以及它们的英文（`related`、`affects`、`linked`、`associated`、`connected`）。

「影响」尤其常见。它不是错的方向，而是**信息量为零**——A 影响 B 可以指供货、竞争、持股、政策约束、预期传导中的任何一种。把它换成实际发生的那一种动作。

超过 8 个字、含有逗号/句号/空白，也会被判为句子。

## 每一族边该带哪些属性

| 关系族 | 至少带 |
| --- | --- |
| 持股 / 控制 | 持股比例、持股数量、股东性质、直接还是间接、报告期、是否一致行动 |
| 供应 / 采购 | 品类、数量或金额、占对方采购/销售比、合同类型、计价方式、有效期间、提前期 |
| 客户 / 销售 | 收入金额、占营收比、期间、是否前五大客户、结算方式 |
| 分部 / 产品 | 收入、成本、毛利率、占比、同比、报告期、口径 |
| 债务 / 担保 | 本金、币种、利率、期限、担保方式、余额时点 |
| 政策 / 监管 | 发布机构、生效时间、适用范围、约束强度、过渡期、罚则 |
| 事件 | 宣布/生效/完成时间、金额、条件、进展状态 |
| 竞争 / 替代 | 重叠市场、份额、替代弹性、价差、期间 |
| 预期 / 估值 | 观察指标、传导时滞、方向、幅度、预测机构、发布时间 |
| 风险传导 | 触发条件、领先指标、传导时滞、影响量级、缓释措施、失效条件 |

属性名同样用中文。数值属性要带单位（写在属性名里，如 `占营收比(%)`、`金额(亿元)`，或值本身带单位后缀）。

## 方向

方向按**动作发出方 → 承受方**：

- 供应：供应商 → 客户
- 持股：股东 → 被持股公司
- 政策约束：政策/监管机构 → 被约束主体
- 预期传导：驱动因素 → 被定价的证券

对称关系（竞争、替代、合资）也要选一个方向写。纵深分析默认按无向遍历，所以方向写错不会让路径消失，但会让 `fg neo4j hop --directed` 和机制方向判断出错。

## 认识状态

边上的 `epistemic` 决定这一跳算不算硬证据：

- `reported` / `observed`：来自披露或市场数据，是纵深的地基。
- `estimate` / `forecast` / `inference` / `scenario`：必须写 `basis_fact_ids`（依据哪些已接受事实）和 `rule`（推断规则）。
- **一条路径上连续超过 2 跳都是推断类，整条路径判为悬空。** 推断边要夹在有据可查的边之间。

推断边还应该在 `mechanism` 里写清替代解释和失效条件。「若客户改用磷酸铁锂路线，此传导减弱」这种一句话，比多连三条边有价值。

## 什么时候合并、什么时候拆分

编译时会自动合并 `(from, to, relation, period)` 完全相同的边，并把事实与属性并到一起。

**该拆成多条边的情况：**

- 不同报告期的同一关系（2024 年持股 12%、2025 年持股 15%）→ 用 `period` 区分。
- 同一对实体之间的不同动作（既供应原料又互为竞争对手）→ 两个 `relation`（`长协供应` 与 `竞争`）。
- 同一动作但机制不同（直接持股 vs 通过合伙企业间接持股）→ `attrs.持股方式` 区分；必要时拆成 `持股` / `间接持股`。

**该合并的情况：** 同一份公告里拆出来的多条属性，应该并到**一条**边的 `attrs` 上，而不是造出多条只差一个属性的平行边。重复边会在质量报告里体现为关系词表虚高、`mean_attr_count` 偏低。

## 自查

```bash
fg quality        # 看 vague_relations / sentence_relations / missing_mechanism / missing_attrs
fg node E-catl    # 看这个节点的进出边，读一遍关系名
```

把某个节点的进出边关系名连起来读一遍。如果读出来像一份目录（`持股`、`长协供应`、`贡献收入`），边就写对了；如果读出来是一串完整句子或「相关、影响、涉及」，那图还没法用。
