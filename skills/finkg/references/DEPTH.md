# 纵深：10 跳要是机制，不是长度

## 什么算一跳

只有**业务实体之间的边**算跳：Company、Stock、Listing、Exchange、Institution、Person、Product、Facility、Commodity、Industry、Segment、Contract、Policy、Regulator、Event、Risk、Expectation、Index…

`Document`、`Source`、`Observation`、`Metric` 这类元节点即使建了也不贡献跳数。原因很直接：「公司 → 文档 → 观测 → 指标 → 公司」能把 0 跳业务距离灌成 4 跳。数值应该是节点属性，不是节点。

`fg depth` 与 `fg quality` 都只在业务子图上算。

## 八个语义层

纵深的本质是**机制在层与层之间传导**。八层是这套传导的骨架：

| 层 | 中文 | 典型内容 |
| --- | --- | --- |
| `policy_regulation` | 政策与监管 | 准入门槛、出口管制、补贴、处罚、税收 |
| `legal_ownership` | 法律与所有权 | 控制、持股、担保、质押、发行、上市 |
| `supply_operation` | 供给与运营 | 采购、产能、投产、代工、物流、库存 |
| `demand_market` | 需求与终端市场 | 客户订单、终端销量、替代、竞争、集采 |
| `firm_action` | 公司行为与战略 | 并购、剥离、扩产、调价、回购、合资 |
| `financial_capital` | 财务与资本 | 分部收入毛利、费用、减值、融资、分红 |
| `expectation_valuation` | 预期与估值 | 指引、一致预期、目标价、指数纳入、估值倍数 |
| `risk_feedback` | 风险与二阶反馈 | 信用敞口、集中度、质押追保、商誉减值、流动性螺旋 |

每条边写一个 `layer`。不写就不参与跨层统计，等于这一跳对纵深没有贡献。

**实践中最常缺的是首尾两层**：`policy_regulation`（链条的起因）和 `risk_feedback`（链条的回授）。缺了它们，图就只有中段的「供应—财务」，看起来有跳数但读不出因果。

## 一条路径算不算真纵深

`fg depth` 对每条路径给出 `substantive: true/false` 和 `weak_because`。四条判据：

### ① 跨层足够

`hops >= 3` 时至少跨 **3 个**语义层。同层内接龙不是纵深，是同一件事的展开。

### ② 关系类型足够多样

不同关系名的数量 ≥ `ceil(hops / 2)`。

这一条专门挡「A供应B、B供应C、C供应D……」这种靠单一关系拉长的链。供应链本身是合法的，但一条 10 跳全是「供应」的链只说明了一件事；掺进政策约束、持股控制、预期传导之后，同样 10 跳才真的是 10 个机制环节。

### ③ 每一跳都有证据

每条边至少一个 `fact_ids`，并且写了 `mechanism`。缺机制的那一跳会被列进 `steps_without_mechanism`——那是链条实际断掉的位置。

### ④ 连续推断不超过 2 跳

连续的 `inference` / `forecast` / `estimate` / `scenario` 超过 2 跳，整条路径判为悬空。推断要夹在有据可查的边之间。

## 独立见证

一条路径不够。`fg depth` 用**边不重叠**（edge-disjoint）的贪心选择挑出独立路径族：共享同一主干、只换尾巴的二十条路径只算一条。

```json
"independent_at_or_above": {"6": 20, "8": 11, "10": 8, "12": 3}
```

意思是：≥6 跳的边不重叠实质路径 20 条，≥10 跳的 8 条。这是**观察指标**，用来判断交叉验证够不够，不是「必须凑满 N 条才许装库」的门槛。

为什么关心边不重叠：**同一个结论有两条独立通路，才叫被图证明过。** 只有一条路时，任何一跳的数据出错，结论就错，而你不会发现。缺独立通路时，`fg brief` 会引导你换来源/换口径再问，而不是让你为跳数接龙。

## 结构指标

`fg depth` 的 `structure` 段：

| 指标 | 健康值 | 不健康说明什么 |
| --- | --- | --- |
| `isolated_nodes` | 空 | 有节点完全没边，属于游离资料 |
| `leaf_ratio` | < 0.45 | 叶节点太多 = 一根主干挂一圈卫星 |
| `two_core_ratio` | > 0.30 | 接近 0 说明图是树/链，没有任何环路 |
| `bridge_ratio` | 越低越好 | 接近 1.0 说明每条边都是唯一通路，断一跳全断 |
| `anchors[].reach_undirected_ratio` | > 0.85 | 锚点走不到的部分与主题无关联 |
| `layers_used` | 向 8 靠拢 | 缺的层就是机制缺的环节；用 `fg brief` 的未覆盖扇区去补 |

`two_core_ratio ≈ 0` + `bridge_ratio ≈ 1.0` 是最典型的病：看着有 8 跳长链，实际上零冗余、零交叉验证。

## 怎么补深

**补深不是「再接一跳」。** 按 `weak_because` 给出的理由分别处理：

| weak_because | 真实缺口 | 补法 |
| --- | --- | --- |
| 只跨 N 个语义层 | 缺的那几层没检索 | 回到 `LAZYSEARCH.md` 的扇区 9（政策事件）、10（预期风险）补检索 |
| 只有 N 种关系，像重复接龙 | 只沿一个维度展开 | 给链上的实体补另一维度的边：持股、政策、竞争、预期 |
| N 跳没有事实支撑 | 那一跳是猜的 | 针对那一跳专门检索，或把它降级为 `inference` 并写 basis |
| N 跳没写机制 | 没想清楚 | 想不清就说明还没研究透，回去查 |
| 连续 N 跳都是推断 | 中间缺硬数据 | 在推断段中间插入一个有披露支撑的节点 |
| 独立见证只有 1 条 | 零交叉验证 | 换来源/换口径给同一结论找第二条通路 |

## 一条 10 跳链应该长什么样

```
能量密度准入政策 ──准入约束──▶ 动力电池产业        [政策与监管]
动力电池产业     ──拉动需求──▶ 电池级碳酸锂        [需求与终端市场]
电池级碳酸锂     ──主要产出──▶ 赣锋锂业            [供给与运营]
赣锋锂业         ──长协供应──▶ 宁德时代            [供给与运营]
宁德时代         ──贡献收入──▶ 动力电池分部        [财务与资本]
动力电池分部     ──整车供应──▶ 特斯拉              [需求与终端市场]
特斯拉           ──预期传导──▶ 宁德时代A股         [预期与估值]
宁德时代A股      ──挂牌────▶ 深圳证券交易所      [法律与所有权]
```

8 跳、6 个语义层、多种关系、每跳有机制。关系名是短语，品类/阈值/板块写在边上的 `attrs` 里。要再深，往两端接**真实存在的环节**：上游接锂矿资源国的出口政策，下游接指数纳入带来的被动配置资金，或者接回二阶反馈——股价下跌影响股权质押率，进而影响大股东的追加担保义务，这一跳会把链条闭环成 `risk_feedback`。

对照一条**假的 10 跳**：公司 → 年报 → 利润表 → 营业收入 → 数值观测 → 数据源 → 公司 → 同一年报……跳数够，业务距离是 0。**不要为了跳数去接龙**；`fg depth` 会因为跨层不足或关系重复把这种链判为非实质，`fg brief` 会改口让你去问还没覆盖的扇区。

## 机制问题

纵深要服务于具体问题，否则就是为了多跳而多跳。把问题写进会话：

```bash
fg session set --mechanism-question '{
  "id": "M1",
  "question": "锂价如何经采购成本与分部毛利传导到盈利与估值",
  "from": "E-lithium", "to": "E-catl-a",
  "min_hops": 5, "independent": 2,
  "layers": ["supply_operation", "financial_capital", "expectation_valuation"],
  "directed": false
}'
```

| 字段 | 含义 |
| --- | --- |
| `from` / `to` | 这条链路必须连通的两端 |
| `min_hops` | 你判断这条机制自然有几环（不是门槛；太大只会逼出灌水路径） |
| `independent` | 希望几条边不重叠的独立见证 |
| `layers` | 这条问题必须跨到的语义层 |
| `directed` | 是否只按方向走 |

`fg depth --case M1` 会逐条检查并给出缺什么。`fg quality` / `fg brief` 会把未走通的机制问题列为 **guide**——优先补它缺的那几跳，而不是去凑节点数。未走通不会让 `ok=false`，也不会拦住装库。

写机制问题的原则：`min_hops` 应该来自你对机制环节数的判断，不是来自想要的数字。锂价到股价确实要经过采购成本、分部毛利、合并利润、盈利预期这几个环节，所以 5 跳是自然的；硬写 12 跳只会逼出灌水路径。

## 在 Neo4j 里验证

```bash
fg neo4j hop --from-id E-lithium --to-id E-catl-a --min-hops 5 --max-hops 12 --limit 5
```
