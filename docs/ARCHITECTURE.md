# 架构

## 数据流

```
        ┌─────────────┐
        │  LazySearch │  HTTP /api/query（结论 + 完整 history）
        │             │  MCP query_financial_data（只有结论）
        └──────┬──────┘
               │  fg search / fg harvest add
               ▼
     ┌──────────────────────────────────────────────┐
     │ harvest/h-000N.json        一次检索的完整落盘 │
     │   ├─ answer     结论                          │
     │   ├─ data       原始工具返回（真正的富矿）     │
     │   ├─ plan       工具调用与执行过的 SQL         │
     │   ├─ provenance 源库表、缓存路径、内部工具名   │
     │   └─ cells      逐单元格清点 → 核账分母        │
     └──────┬───────────────────────────────────────┘
            │  草稿只写进会话 drafts/，再 mine 进 jsonl
            ▼
     entities.jsonl ──┐
     facts.jsonl ─────┤  fg compile（确定性重建）
     session.json ────┘
            │
            ▼
        graph.json  ── fg neo4j load ──▶  Neo4j（单事务替换 + 读回核对 + 失败回滚）
            │                                    │
            ├── fg quality / fg depth            └── fg neo4j hop / query（库内验证多跳）
            └── fg export（中文表头 CSV + 图 + 事实 + 台账 + 报告）
```

**真源只有三个文件**：`harvest/`、`entities.jsonl`、`facts.jsonl`（加会话元数据）。
`graph.json` 和全部报告都是可重建的读模型——删了重跑 `fg compile` 就回来。

## 模块

| 模块 | 行数 | 职责 |
| --- | --- | --- |
| `fg.py` | ~1,150 | CLI 入口。子命令分派、信息利用率核账、质量报告组装、热上下文 |
| `fgmodel.py` | ~440 | 事实/实体内容校验、图编译、节点丰富度与边可分析性度量、冲突检测 |
| `fgneo4j.py` | ~360 | Neo4j HTTP 事务桥：建库、批量装载、读回核对、多跳查询、GraSS |
| `fglazy.py` | ~320 | LazySearch 双通道、返回切层、出处抽取、数据单元格清点 |
| `fgdepth.py` | ~300 | 业务子图、路径枚举、实质性判定、独立见证、结构指标 |
| `fgstore.py` | ~290 | 会话目录、原子写、JSONL、收割仓库、明文台账、编码兜底 |
| `fgconfig.py` | ~100 | 配置优先级与密钥隔离 |

全部只用 Python 标准库。约 2,950 行。

## 关键设计决定

### 落盘先于使用，引文必须可核验

事实的 `quote` 必须是对应收割落盘文本的子串（空白与千分位差异宽容，内容差异不宽容）。
这一条把「模型说这个数是 X」变成「这个数出自这次检索的这一行」。

代价是挖掘时必须回去摘原文，不能凭记忆写。收益是整张图任何一个数字都能一路回溯到检索原文。

### 结论只占返回信息量的 4%，所以核账分母是单元格

实测一次 LazySearch 返回：结论 474 字符，`history` 里的原始工具返回 11,814 字符。
只看结论就丢掉 96% 的检索成果，而丢掉的恰恰是能让节点属性变丰富的那部分。

于是把返回切成四层，并把**答案与原始返回里的表格单元格 + 正文数值**清点出来作为分母。
LazySearch 自己的 knowledge card（prompt）、执行的 SQL、缓存路径不计入——它们是查询机制不是数据。

判定「已用」的规则是单元格取值出现在某条事实的 `quote`、`object.value` 或边属性里。
所以摘整行比摘单个数字划算，这也顺带鼓励了更好的回溯粒度。

### 属性用中文点分层级，维度组由命名派生

`财务.利润表.2025年报.营业总收入` 的第一段 `财务` 自动成为维度组。好处：

- 维度覆盖统计不需要额外元数据，改个命名就改了分组
- 同一指标多期共存不会互相覆盖
- Neo4j 里属性通过参数化 map 写入，中文和点号都不需要转义

代价是命名纪律要靠文档约束而非代码强制——这是刻意的，因为强制字段表会退化成填空。

### 只有业务实体跳算跳

`Document` / `Observation` / `Metric` 这类元节点不贡献跳数，实践中也基本不需要建：
数值直接做节点属性就够了。这一条挡掉最常见的灌水形态——
「公司 → 年报 → 利润表 → 营业收入 → 数值观测 → 数据源 → 公司」跳数够而业务距离是 0。

### 长路径的实质性用四条独立判据把关

跨层数、关系类型多样性、逐跳证据与机制、连续推断长度。再加边不重叠的独立见证。

其中「关系类型数 ≥ ⌈跳数/2⌉」是专门挡单一关系接龙的。供应链接龙本身合法，
但一条 10 跳全是「供应」的链只说明了一件事；掺进政策约束、持股控制、预期传导之后，
同样 10 跳才真的是 10 个机制环节。

### 装载是单事务整库替换 + 读回核对

在同一事务里写完就读回来比对总数、逐标签数、孤立节点数，不符则整体回滚。
所以装载要么完整成功，要么库完全没动，不会留下半张图。

节点同时带技术标签 `FGNode` 与语义标签，唯一约束建在 `FGNode.id` 上，所以 MATCH 走索引。
关系类型用 2–8 字中文短语——Browser 图例能扫读，代价是关系类型仍然不少，
通用查询要用 `type(r)` 而不是写死类型名。

### 没有 Gate、签名、令牌、哈希链

上一代实现有八道阻断门 + HMAC attestation + 一次性 resume token + 工件哈希链。
去掉的理由：**它们保护的是流程合规，不是判断质量。**

- 哈希链校验的是「工件有没有变」，不是「内容对不对」
- HMAC attestation 在 Agent 与签名器同进程时无法抵抗恶意 Agent，只增加摩擦
- 一次性 token 让上游一改动就要重走全部下游审批，实际效果是鼓励少改

替代方案是结构化提问 + 明文台账。台账记录的是「我们商量过什么」，不是「谁被授权了」。
这个选择明确放弃了「防恶意 Agent」这个目标——工具只承诺协作可追溯，不承诺对抗性安全。

### 质量校验只判内容

不检查 JSON 键位、不算工件哈希、不把节点数量当目标。判的都是「人能不能用」：
数字有没有口径、引文能不能找到、节点够不够支撑判断、边说不说得清机制、
路径是不是真跨了机制层、检索数据有多少进了图。

`business_node_count` 统计的是有证据的业务节点，所以拆分同一实体、批量导入空壳都不会让它变好看。

失败语义：有证据缺陷（引文找不到、端点悬空）时不该把图当结论用，装库也会拒绝这类错误。
节点数、边数、跳数**不是**失败条件，也不拦住装库。
它不阻止任何人类决定。

## 渐进式披露的三层

1. **SKILL.md**（~250 行）：router + 硬规则 + 命令索引。agent 启动只加载 frontmatter。
2. **references/**（7 份）：某件事做之前才读那一份。
3. **收割落盘**：几万字符不进上下文，用 `fg harvest show --part … --grep …` 按需取片段。

第 3 层常被忽略但最关键：它让「大量检索」和「有限上下文」不再矛盾。

## 平台适配

| 事项 | 处理 |
| --- | --- |
| Windows PowerShell 按控制台宽度折断长输出 | 全局 `--out-file` 让工具自己写文件；`>` 和 `Out-File` 都不可靠 |
| PowerShell `>` 写 UTF-16 BOM | 读取时自动嗅探 BOM（UTF-8/16/32），并给出指向 `--out-file` 的报错 |
| Windows 无符号链接权限 | `install.py` 自动回退为复制并提示 |
| argparse 子解析器默认值覆盖父层 | 两阶段解析，全局选项放子命令前后都生效 |
| Neo4j 社区版无多库 | `ensure-db` 明确提示改用 `--database neo4j` |
| `/mcp/` 尾斜杠 307 重定向 | MCP 客户端跟随重定向（最多 3 次） |
| LazySearch 返回可能是 SSE | 同一客户端同时处理 JSON 与 `text/event-stream` |

## 不做的事

- 不做本体工程。类型只用来区分「公司/股票/上市记录/事件/风险不是一回事」，不做 OWL 建模。
- 不做 NLP 分词。`--grep` 是你给的正则，工具不猜你想找什么。
- 不在 skill 代码里做领域关键词硬匹配。空泛关系表是唯一例外，且它是显式的一张短表。
- 不自主交易、开户、授信、估值签字或对外发布结论。
